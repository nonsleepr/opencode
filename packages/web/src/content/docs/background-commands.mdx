OpenCode can run long-running commands in the background without blocking your workflow. This lets you start development servers, run builds, or execute tests while continuing to work on other tasks.

The agent automatically manages these background processes and can check their status or retrieve their output at any time.

---

## How it works

When you ask OpenCode to run a command that takes more than 10 seconds, it automatically moves to the background. You can also explicitly ask for commands to run in the background from the start.

Background processes continue running while you chat with the agent or work on other tasks. The agent can check on them, retrieve their output, send input to interactive programs, or terminate them when needed.

---

## Common use cases

Run development servers, execute test suites, or build projects in the background while continuing other work. OpenCode automatically manages these processes and can check their status or output at any time.

```
"Start the dev server in the background and then update the API routes"
```

```
"Run the test suite in the background and show me the results when done"
```

---

## Architecture

OpenCode uses several tools to manage background processes.

---

### Process management

When a command runs in the background, OpenCode receives a process ID (PID) that identifies it. The agent uses this PID to track and interact with the process throughout its lifecycle.

Background processes have three main tools available:

- **bash tool** - Runs commands, with optional `run_in_background` parameter
- **process_output tool** - Retrieves current output and status of a background process
- **process_input tool** - Sends input to interactive background processes

---

### Output handling

The agent can retrieve output from background processes at any time. Output includes both stdout and stderr, interleaved in chronological order by default for accurate debugging.

For processes with heavy output, the agent can filter to show only stdout or only stderr. This helps isolate specific information like build logs or error messages.

---

### Process lifecycle

Background processes remain available even after they complete. The agent can retrieve output from finished processes, making it easy to check results later.

When you close OpenCode or end your session, all background processes are automatically terminated and cleaned up.

---

## System limits

OpenCode maintains some limits on background processes to ensure system stability.

A maximum of 50 background processes can run simultaneously. Output is limited to 30KB per stream (stdout/stderr) or 60KB combined, with truncation showing the most recent content when limits are exceeded.
